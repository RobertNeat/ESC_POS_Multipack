# Dobór technologii i wykonania poszczególnych elementów systemu

Plik określający sposób implementacji części systemu i stosu technologicznego

| Część systemu       | Sposób implementacji                  | Technologia      | Biblioteki                                      |
| ------------------- | ------------------------------------- | ---------------- | ----------------------------------------------- |
| Printer_Adapter     | library package (DependencyInjection) | TypeScript       | @node-escpos                                    |
| POS_8370_Adapter    | library package (DependencyInjection) | TypeScript       | @node-escpos                                    |
| Type_Writer_Service | frontend + service                    | NestJS + Angular | Primng_v21 or OptimusUI_v1, Swagger             |
| Artifact_Storage    | service/storage                       | Spring Boot      | Java NIO                                        |
| Template_Service    | service                               | Spring Boot      | Spring Data JPA, Hibernate,Liquibase,PostgreSQL |
| Document_Service    | service                               | Spring Boot      | Spring Data JPA, Hibernate,Liquibase,PostgreSQL |
| Document_Renderer\* | service                               | JasperReports    |                                                 |
| Print_Service       | service                               | NestJS           | RabbitMQ client, Liquibase/TypeORM              |
| Print_Worker        | service                               | NestJS           | @node-escpos                                    |

\* document renderer - Jasper powinien być równoległą opcją rendereradla plików PDF, dla POS powinien być rendered renderujący wydruki jako komendy POS (JasperPDFRenderer)
Wersja implementacji EscPosRenderer zwraca dokument jako komendy POS, ale to Adapter wydruku i adapter konkretnego modelu drukarki wiedzą do jakiego urządzenia trafi ten dokument
